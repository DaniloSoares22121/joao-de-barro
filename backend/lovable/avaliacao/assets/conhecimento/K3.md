# K3 — Entrada de um avaliador novo no sistema
Versão 1.1 — 14/11/2026. Como o sistema conhece um avaliador que não é o Alan e monta a camada dele (D-058, D-061, D-094 a D-097). A versão 1.0 está guardada em `jdb-treino/referencia/conhecimento/_backup/`.
**Regra de ouro:** o sistema pergunta só o que muda o resultado, uma pergunta por vez. O que não for perguntado segue a base geral (K0) até o avaliador mudar.

## 1. Cadastro (primeiro acesso)
| Campo | Para quê |
|---|---|
| Nome como sai no laudo | capa, rodapé, assinatura |
| CRECI e CNAI | competência (item 3); sem CNAI, o sistema não emite PTAM, só OV |
| Cidade e região de trabalho | pesquisa de mercado e cadastro municipal |
| Modalidades que faz (OV, AM, AM garantia, AMJ) | o que o sistema oferece |
| Tipos de imóvel (casa, apto, lote, galpão, sala, rural…) | quais fichas carregar |
| Contatos para o currículo | anexo de currículo, com links |
| Logo e cores | identidade visual do laudo. O avaliador envia a logo e escolhe as cores; o sistema não cria logo nem marca. Sem logo, o laudo sai com visual neutro, sem marca (D-095) |
| Formação (sem certificados) | anexo de currículo |
| Tabela de preços, prazos e forma de pagamento | proposta e contrato. A tabela é dele; sem tabela, o campo de preço fica em branco para ele preencher. O sistema não sugere preço (D-097) |

- **Autorização da base comum:** "Compartilhar meu raciocínio com a base comum, sem dados de clientes?" (sim / não, com a data). Sem aceite, o que ele ensina fica só nele.
- **Dados sensíveis do avaliador** (CPF, endereço, Pix) ficam só na configuração, nunca na base nem no git.

## 2. Modelos: "Me mande laudos que você já fez" (D-094)
- O sistema tem laudos modelo prontos, mas o avaliador escolhe: usar os do sistema ou subir os dele.
- A maioria dos avaliadores tem laudos prontos. Pedir de 1 a 3 laudos recentes, de preferência um de cada modalidade que ele faz.
- **Antes de guardar qualquer coisa:** tirar os dados de clientes:
  - nomes, CPF/CNPJ;
  - endereço, quadra, lote, matrícula, inscrição;
  - links do mapa, fotos e documentos.
  Os valores passam a faixa.
- **O que o sistema tira dos laudos dele:**
  - estrutura e ordem dos itens;
  - redação típica (frases fixas, limitação de uso, ressalvas);
  - identidade visual;
  - regras implícitas: base de cálculo, faixa, arredondamento, homogeneização, quantos referenciais usa, quais sites pesquisa, se tarja documentos;
  - tamanho típico.
- **Mostrar o que foi entendido, em tópicos, e pedir confirmação.** Só o que ele confirmar vira regra dele.

## 3. Sem laudos: o laudo geral e "vamos fazer juntos" (D-094)
- **Ponto de partida:** o laudo geral, um modelo que o Alan deixa disponível no sistema, sem nenhum dado de cliente e sem os dados do Alan.
- **O avaliador diz o que quer fazer** ("quero fazer uma opinião de valor", "quero um PTAM judicial"). O sistema ensina a modalidade (K0.2) e monta junto com ele, perguntando nos pontos de decisão.
- **O primeiro laudo aprovado de cada modalidade vira o modelo dele** daquela modalidade. Depois disso, ele personaliza para cada cliente.

## 4. Proposta e contrato (D-097)
- **O Alan deixa uma proposta modelo e um contrato modelo** no sistema, sem os dados, os preços e as condições pessoais dele.
- **Escolha do avaliador, separada para laudo, proposta e contrato:** usar o modelo do sistema ou subir o seu. Quem sobe a proposta e o contrato dele passa a usar os dele. O sistema tira os dados de clientes antes de guardar e marca os campos que vai preencher em cada trabalho.
- **Com o modelo do sistema, o avaliador ajusta** prazos, cláusulas, dados dele e forma de pagamento. O preço vem da tabela dele (item 1).
- **Estrutura comum** que continua valendo: K0.10 (sinal como arras, assinatura pelo gov.br, frase positiva de competência, upgrade para judicial).

## 5. Perguntas de perfil (só quando o caso precisar)
1. Base do cálculo usual: área construída ou total do terreno?
2. Faixa de variação que costuma declarar (ex.: ±10%)?
3. Arredondamento do valor (milhar, dezena de milhar)?
4. Limite de coeficiente de variação, e o que faz quando passa?
5. Homogeneiza? Com quais fatores e tabelas?
6. Mínimo de referenciais?
7. Sites onde pesquisa, além dos portais grandes?
8. Tarja documentos no laudo do cliente?
9. Validade do parecer?
10. Anexos que sempre usa?
11. Nome do arquivo final?
12. Vistoria própria ou por parceiro?

## 6. Aprender no trabalho e mudar as regras (D-096)
- **Correção ou resposta que muda o resultado:** perguntar "Vale só para este laudo ou para todos os seus?".
  - "Todos os meus": vira regra dele, com o trabalho de origem.
  - "Só este": fica no caso.
  - Nada vira regra sem essa pergunta.
- **Liberdade total para as regras dele:** o avaliador pode mudar qualquer regra de método, de redação ou de formato só para ele, na tela "Minhas regras". Exemplo: o limite de 15% de dispersão.
- **Mudança que contraria lei ou norma conferida na P4** (ex.: citar a Res. COFECI 957/2006, revogada): o sistema avisa uma vez, com a fonte, e respeita a escolha dele.
- **Toda mudança fica registrada:** data, regra, antes e depois.
- **Regras na base comum:** com a autorização, as regras dele entram na fila de curadoria como "aprendido". Só viram "validado" com aprovação do curador. Para os outros avaliadores aparecem como sugestão, com aviso.

## 7. Especialidade que a base ainda não tem (ex.: rural)
- **Pedido de modelo ou de regra sem fichas na base:**
  - responder "ainda não tenho base para isso";
  - mostrar só o que vem da fonte oficial (P4);
  - oferecer fazer o primeiro trabalho junto. **Nunca inventar.**
- **O que esse avaliador ensinar** vira fichas com a etiqueta da especialidade, protegidas e em curadoria.
- **Depois de validadas**, qualquer avaliador pode pedir "Me mostre como se faz um laudo rural" e recebe a estrutura e o raciocínio, sem dados de clientes.

## 8. O que nunca fazer (não são regras do avaliador, são do sistema)
- Inventar dado: área, data, anúncio, documento, norma ou credencial.
- Usar dado de cliente de um avaliador no trabalho de outro.
- Copiar laudo de um avaliador para outro. Só o raciocínio, protegido e validado, circula.
- Mostrar a tabela de preços de um avaliador para outro.
- Aceitar regra de terceiro como validada sem curadoria.
- Criar logo ou marca para o avaliador.
- Imitar assinatura.
